# PyTorch for Demucs and (via faster-whisper/ctranslate2) lyrics
# transcription. Installed separately (see README) so this file alone is not
# enough to reproduce the env with a plain `pip install -r requirements.txt`
# -- torch/torchaudio must be installed first via one of:
#   - NVIDIA GPU present: pip install torch==2.13.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu130
#     (plain `pip install torch torchaudio`, with no --index-url, installs the
#     CPU-only wheel from PyPI even on a machine with a working NVIDIA GPU --
#     confirmed the hard way: this is not a fallback, it silently never uses
#     the GPU. Match the cu1xx tag to the installed driver's CUDA version,
#     e.g. via `nvidia-smi`.)
#   - No NVIDIA GPU: pip install torch torchaudio (plain PyPI, CPU-only)
# Device selection at runtime (which of the above is actually in effect) is
# handled by audio_pipeline/device.py via torch.cuda.is_available(), no
# separate code branch needed.
demucs>=4.0.0,<5

# basic-pitch requires TensorFlow as a hard base dependency on Windows/Linux
# (the [onnx] extra only *adds* onnxruntime as an alternative backend, it
# does not remove the TensorFlow requirement). The actual conflict the spec
# warned about: basic-pitch pins tensorflow<2.15.1, which has NO wheels for
# Python 3.12 at all on this platform -- this is why the project venv is
# pinned to Python 3.11 (see README). On 3.11, tensorflow 2.15.0 installs
# alongside torch 2.13+ with no dependency conflict.
basic-pitch[onnx]>=0.3.0

# Pinned explicitly: tensorflow 2.15 (pulled in by basic-pitch above) was built
# against numpy's 1.x C-API and fails to import ("AttributeError: _ARRAY_API not
# found") under numpy 2.x. audio-separator (see the BS-RoFormer separation model
# below) declares numpy>=2 but has been confirmed to import and run fine under
# numpy<2.0 in this same venv regardless -- that declared constraint isn't
# actually load-bearing at runtime, so this pin resolves the conflict for both.
numpy<2.0

# Pulled in transitively by basic-pitch, but imported directly by

# faster-whisper's backend (ctranslate2) links its own CUDA 12 cuBLAS at
# runtime, independent of whatever CUDA version torch itself was installed
# with (see the cu130 torch install above) -- on a GPU/Windows machine,
# without this, the first real GPU transcription fails with "cublas64_12.dll
# is not found or cannot be loaded" even though torch.cuda.is_available() is
# True. This package just ships that one DLL; audio_pipeline/device.py wires
# its directory onto the DLL search path/PATH automatically. Harmless no-op
# on CPU-only or non-Windows setups (device.py only touches it when both
# conditions apply, and this package installs fine there regardless).
nvidia-cublas-cu12; sys_platform == "win32"

# CTC forced alignment (audio_pipeline/forced_alignment.py): once lrclib gives known-correct
# lyrics text, these align that text directly against the vocal stem to get real per-word
# timestamps, instead of trusting/correcting lrclib's own approximate line-level timing. Uses
# Meta's MMS wav2vec2 CTC model (multilingual, covers English and Cantonese) via `transformers`,
# romanized through `uroman`, with the actual alignment computed by
# `torchaudio.functional.forced_align` (already ships with the `torch`/`torchaudio` install this
# project requires separately -- see the top of this file). Deliberately NOT depending on the
# `ctc-forced-aligner` PyPI package that implements the same idea end-to-end: its C++ extension has
# no prebuilt Windows wheel and fails to build here without MSVC Build Tools; this project
# reimplements the (small, MIT/BSD-licensed) alignment logic directly against torchaudio's already-
# prebuilt equivalent instead. The default alignment model
# (MahmoudAshraf/mms-300m-1130-forced-aligner, downloaded from the Hugging Face Hub on first use)
# is CC-BY-NC 4.0 licensed -- fine for this personal-use project, but not for commercial use.
transformers>=4.40.0
uroman>=1.3.0
